# ✅ 订单创建与支付流程设计

---

## 🔐 1. 提交订单前：生成加密 Token

- 客户端在请求创建订单前，后端生成并返回一个 **订单提交 Token**
- 用于防止重复提交、防刷、防纠改

### 实现建议：

- Token 结构：JWT / HMAC / AES 加密的临时凭证
- 内容包含：用户ID、时间戳、下单内容Hash
- 过期时间：1】5 分钟
- 可存在 Redis 或加密签发（Stateless）

---

## 📅 2. 提交订单后：生成订单数据 + 入队缓存+日志记录

- 校验订单 Token
- 后端进行以下操作：
  1. 生成内部订单号（ORD2025071012310001 类型）
  2. 异步或同步调用微信接口，获取支付单号 + 参数
  3. 构建订单数据结构
  4. 存入内存队列（Redis Hash / ZSet / 自建链表）

### 策略建议：

- Redis Hash: `pending_order:{userId}` 存储 orderId 对应数据
- Redis ZSet: 按时间排序，便于定时清理

---

## 🔀 3. 返回前端：待支付信息

- 返回内容：

```json
{
  "orderId": "ORD2025xxxxxx",
  "amount": 99.9,
  "wxPayParams": {
    "appId": "xxx",
    "timeStamp": "xxx",
    "nonceStr": "xxx",
    "signType": "MD5",
    "paySign": "xxxx"
  }
}
```

---

## 💰 4. 用户发起支付

- 前端调用 `wx.requestPayment({...})`
- 支付后返回前端，系统状态未确认

---

## 🔍 5. 查询支付结果

### 方式一：前端轮询

- 接口：`GET /api/order/status?orderId=xxx`
- 后端先查 Redis，再查 DB

### 方式二：微信支付回调

- 后端接收微信 notify\_url 通知
- 验签 成功 后进行入库 + Redis 维护

---

## 🗂️ 6. 入库 + 队列删除

- 调整 Redis 订单状态为 paid 或直接 DEL
- 写入数据库：
  - `order` 表
  - `payment` 表

---

## 📆 附加功能

### 7. 查看用户待支付订单

- API：`GET /api/order/pending?userId=xxx`
- 从 Redis Hash 中查找

### 8. 定期清理 Redis 过期订单

- 1 小时未支付 → 清除

#### 方法一：Redis ZSet + 时间分辨

```bash
ZREMRANGEBYSCORE pending_orders 0 <now - 3600>
DEL pending_order:{userId}:{orderId}
```

#### 方法二：设置 TTL

- 订单缓存 setex 或 expire 3600 秒

---

## ✅ 总结流程图

```text
[提交订单] → [校验 Token] → [生成订单号 + 微信支付单]
              ↓
       [订单缓存至 Redis]
              ↓
        [返回前端支付参数]
              ↓
     [用户发起支付 wx.requestPayment]
              ↓
    └➔  轮询接口查询支付状态
     ┌────────────┐
[微信支付回调 notify_url]
     ↓
[验签 → 修改订单状态]
     ↓
[写入 DB + 清除 Redis + 推送通知]
```
