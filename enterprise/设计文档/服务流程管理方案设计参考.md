
# 通用B2B服务流程管理方案文档

---

## 一、各服务分类典型执行流程

| 服务分类   | 服务类型       | 典型执行流程节点（顺序）                                          | 备注                          |
|------------|----------------|-----------------------------------------------------------------|-----------------------------|
| 财税服务   | 周期性/一次性  | 订单确认 → 资料收集 → 申报处理 → 结果交付 → 审核确认 → 完成         | 月度记账为周期，报税申报可为一次  |
| 人力资源   | 周期性         | 订单确认 → 需求确认 → 招聘/派遣 → 入职手续办理 → 过程管理 → 报告反馈 → 完成 | 多为持续周期服务                 |
| 工商注册   | 一次性         | 订单确认 → 资料收集 → 材料提交 → 审核跟进 → 证照领取 → 完成           | 典型一次性流程                 |
| 知识产权   | 一次性         | 需求评估 → 申请准备 → 递交申请 → 审查反馈 → 授权/异议处理 → 完成       | 申请流程较长，节点明确           |
| 科创申报   | 一次性         | 需求确认 → 方案制定 → 申报提交 → 过程跟踪 → 审批结果 → 项目结项        | 政府申报，重审批及跟踪           |
| 数字化     | 周期性         | 需求沟通 → 方案设计 → 实施开发 → 测试验收 → 交付培训 → 维护支持         | 项目周期长，包含维护            |
| 创业运营   | 一次性/周期性  | 策划方案 → 执行跟进 → 反馈调整 → 完成总结                            | 有项目型和持续型               |
| 法律服务   | 一次性         | 咨询确认 → 方案制定 → 文件起草 → 审核签署 → 案件/事务跟进 → 结案      | 过程多变，注重文档和沟通         |
| 资质认证   | 一次性         | 需求确认 → 材料准备 → 申请提交 → 审核答复 → 现场验收 → 证书颁发        | 资料合规和现场验收关键           |
| 融资服务   | 一次性         | 需求评估 → 方案设计 → 材料准备 → 融资申请 → 审核反馈 → 融资到账 → 完成   | 资金流转为主，流程长             |
| 品牌推广   | 周期性         | 策划方案 → 设计制作 → 投放执行 → 监测优化 → 项目总结                   | 持续投放、迭代优化             |
| 办公设施   | 一次性         | 需求确认 → 方案制定 → 采购执行 → 安装验收 → 售后服务                    | 交付和验收流程为核心             |

## 二、设计方案概述

1. **模块化设计**  
   - 订单管理  
   - 流程定义与配置  
   - 流程执行与状态管理  
   - 周期任务管理（针对周期性服务）  
   - 角色权限与任务分配  
   - 进度监控与异常处理  
   - 用户交互与反馈

2. **配置驱动流程**  
   采用流程模板（JSON或数据库配置），各服务调用对应流程模板实现流程驱动。

3. **数据驱动状态机**  
   通过订单和流程实例状态字段，控制流程执行推进。

4. **统一接口设计**  
   提供标准接口实现流程推进、任务更新、状态查询。

5. **灵活扩展**  
   支持周期服务的周期任务自动生成和状态管理，未来支持并行、多分支。

## 三、数据库设计

### 1. 服务订单表 `service_order`

| 字段名       | 类型          | 说明                      |
|--------------|---------------|---------------------------|
| order_id     | varchar(64)   | 订单ID，主键              |
| user_id      | varchar(64)   | 用户ID                    |
| service_id   | varchar(64)   | 服务ID                    |
| service_type | enum          | 服务类型(one_time, recurring) |
| status       | enum          | 订单状态(Pending, Active, Paused, Completed, Cancelled) |
| current_step | varchar(50)   | 当前流程步骤名称          |
| start_date   | datetime      | 服务开始时间              |
| end_date     | datetime      | 服务结束时间              |
| created_at   | datetime      | 创建时间                  |
| updated_at   | datetime      | 更新时间                  |

### 2. 流程模板表 `process_template`

| 字段名       | 类型        | 说明                     |
|--------------|-------------|--------------------------|
| template_id  | varchar(64) | 模板ID，主键             |
| service_id   | varchar(64) | 关联服务ID               |
| template_name| varchar(100)| 模板名称                 |
| steps_json   | text        | 流程步骤JSON数组（步骤名称、顺序、角色等）|
| created_at   | datetime    | 创建时间                 |
| updated_at   | datetime    | 更新时间                 |

### 3. 周期任务表 `service_cycle_task`

| 字段名         | 类型          | 说明                         |
|----------------|---------------|------------------------------|
| task_id        | varchar(64)   | 任务ID，主键                 |
| order_id       | varchar(64)   | 关联订单ID                   |
| cycle_number   | int           | 周期号                       |
| cycle_start    | datetime      | 周期开始时间                 |
| cycle_end      | datetime      | 周期结束时间                 |
| status         | enum          | 任务状态(Pending, InProgress, Completed) |
| deliverables   | text          | 交付物描述                   |
| created_at     | datetime      | 创建时间                     |
| updated_at     | datetime      | 更新时间                     |

### 4. 流程实例表 `process_instance`

| 字段名         | 类型          | 说明                     |
|----------------|---------------|--------------------------|
| instance_id    | varchar(64)   | 实例ID，主键             |
| order_id       | varchar(64)   | 关联订单ID               |
| template_id    | varchar(64)   | 流程模板ID               |
| current_step   | varchar(50)   | 当前步骤名称             |
| status         | enum          | 状态(NotStarted, InProgress, Completed, Cancelled) |
| created_at     | datetime      | 创建时间                 |
| updated_at     | datetime      | 更新时间                 |

## 五、流程执行与状态管理

- **启动流程**  
  创建流程实例，初始化状态`NotStarted`，当前步骤指向第一节点。

- **推进流程**  
  任务完成后，调用接口将当前步骤状态设为`Completed`，推进到下一个步骤，更新订单`current_step`。

- **异常处理**  
  支持流程暂停、取消、退回重做。

- **周期任务管理**  
  周期性服务，根据订单周期自动生成`service_cycle_task`，每周期任务独立执行。

## 六、管理与监管

- **进度监控**  
  管理员与用户均可查看订单和流程实例的当前状态及历史记录。

- **任务分配**  
  流程节点绑定角色与责任人，支持任务催办与提醒。

- **异常报警**  
  超时未处理自动提醒或报警。

- **日志审计**  
  记录操作日志与流程变更，便于追溯与合规。

## 七、编码方案建议

- **ID编码**  
  采用前缀+时间戳+随机码，如：`ORD20250710123000123`、`TPLACCT20250710A001`。

- **状态字段**  
  使用枚举类型统一管理，便于状态转换和校验。

- **接口规范**  
  RESTful API，支持流程查询、推进、回退、取消操作。

- **流程定义格式**  
  采用JSON格式存储流程模板，方便修改和扩展。

---

## 八、总结与扩展

- 本方案满足多种服务分类及周期/一次性服务流程管理  
- 采用配置驱动流程，便于灵活适配不同业务  
- 支持周期任务自动管理，保障周期服务闭环  
- 后续可扩展审批流、并行流程、条件跳转等高级功能
