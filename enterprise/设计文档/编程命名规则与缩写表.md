# 编程命名规则与常用缩写表

## 一、命名方法建议

1. **使用驼峰命名法（camelCase）** 命名函数、变量、字段：如 `getUserInfo`, `fetchData`  
2. **布尔变量以 `is` / `has` / `should` 开头**：如 `isLoggedIn`, `hasPermission`, `shouldReload`  
3. **避免上下文冗余**：在 `User` 对象内部就不要使用 `userName`，使用 `name` 即可  
4. **简化模块字段命名**：在 `Order` 模块中，`orderDate` 可简化为 `date`  
5. **引入标准缩写** 避免重复长词：如 `configuration` → `config`，`application` → `app`  
6. **状态变量可使用后缀标记来源**：如 `xxxRaw`（原始）、`xxxCached`（缓存）、`xxxState`（状态）

## 三、命名优化示例

| 冗长命名                       | 优化命名     | 说明             |
|--------------------------------|--------------|------------------|
| getUserInformation             | getUserInfo  | 简化 information |
| fetchDataFromServer           | fetchData    | 上下文已暗示来源 |
| isUserAuthenticated            | isAuth       | 主语省略         |
| calculateTotalAmountOfItems    | calcTotal    | 合并语义         |
| shouldDisplayBanner            | showBanner   | 省略 should      |

## 四、方法命名常用前缀

| 前缀     | 用途说明             |
|----------|----------------------|
| get      | 获取某个值（同步）   |
| fetch    | 拉取数据（通常异步） |
| set      | 设置某个属性值       |
| update   | 更新某个对象或值     |
| delete / remove | 删除某项       |
| is / has / can / should | 布尔判断 |
| init     | 初始化               |
| load     | 加载资源或数据       |
| render   | 渲染 UI 或组件       |
| handle   | 处理事件/动作       |
| validate | 校验数据/输入       |

---

建议结合上下文、领域术语、团队风格，保持命名一致性与可读性。
